## Exercício 1 — Criando CATEGORIA

```sql
CREATE TABLE categoria (
    id_categoria BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);
```

---

## Exercício 2 — Conferindo a estrutura

Após executar no SQL Editor do Supabase e verificar no Table Editor:

1. **Quais colunas foram criadas:**
   - `id_categoria`
   - `nome`

2. **Qual é a chave primária:**
   - `id_categoria`

3. **Qual coluna possui NOT NULL:**
   - `nome` (porque foi definida como NOT NULL)

4. **Qual coluna possui geração automática:**
   - `id_categoria` (por causa do `GENERATED BY DEFAULT AS IDENTITY`)

## Exercício 3 — Criando PRODUTO

```sql
CREATE TABLE produto (
    id_produto BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco NUMERIC(10,2) NOT NULL CHECK (preco >= 0),
    estoque INTEGER NOT NULL DEFAULT 0 CHECK (estoque >= 0),
    id_categoria BIGINT NOT NULL,
    CONSTRAINT fk_produto_categoria
        FOREIGN KEY (id_categoria)
        REFERENCES categoria(id_categoria)
);
```

## Exercício 9 — Primeiro SELECT

```sql
SELECT *
FROM categoria;
```

**1. De onde vieram os valores de `id_categoria`?**
Foram gerados automaticamente pelo PostgreSQL, porque a coluna é `GENERATED BY DEFAULT AS IDENTITY`.

**2. Por que `ativo` recebeu um valor sem ser informado no `INSERT`?**
Porque a coluna `ativo` foi criada com `DEFAULT TRUE`. Quando não informamos um valor, o banco usa o valor padrão.

## Exercício 15 — Testando NOT NULL

**Antes de executar:**

> O PostgreSQL deverá aceitar o registro? Por quê?

**Não.** Porque a coluna `nome` foi criada com `NOT NULL`, então é obrigatório informar um valor.

**Tentativa:**

```sql
INSERT INTO produto (preco, estoque, id_categoria)
VALUES (100.00, 5, 1);
```

**Resultado:** o banco rejeita a inserção. A restrição responsável é o `NOT NULL` da coluna `nome`.

## Exercício 16 — Testando CHECK

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Monitor', -500.00, 10, 1);
```

**1. O registro foi inserido?**
Não.

**2. Qual restrição foi envolvida?**
`CHECK (preco >= 0)`.

**3. Qual regra foi violada?**
O preço não pode ser negativo.

## Exercício 17 — Testando a chave estrangeira

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Produto Teste', 100.00, 5, 9999);
```

**Antes de executar:**

> O banco deveria permitir essa inserção? Por quê?

**Não.** Porque `id_categoria` é uma chave estrangeira que referencia `categoria(id_categoria)`. Se a categoria 9999 não existe, a inserção quebraria a integridade referencial.

**Depois de executar:**

O banco rejeita a inserção com um erro de integridade referencial (foreign key violation). Isso acontece porque não existe nenhuma categoria com `id_categoria = 9999` na tabela `categoria`. A regra da FK impede que um produto aponte para um registro inexistente.

## Exercício 18 — Identifique os problemas

### A

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Teclado', -150.00, 10, 1);
```

1. **Problema:** preço negativo.
2. **Restrição violada:** `CHECK (preco >= 0)`.
3. **Corrigido:**

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Teclado', 150.00, 10, 1);
```

---

### B

```sql
INSERT INTO produto (preco, estoque, id_categoria)
VALUES (250.00, 5, 1);
```

1. **Problema:** falta o campo `nome`, que é obrigatório.
2. **Restrição violada:** `NOT NULL` na coluna `nome`.
3. **Corrigido:**

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Nome do Produto', 250.00, 5, 1);
```

---

### C

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Webcam', 300.00, -2, 1);
```

1. **Problema:** estoque negativo.
2. **Restrição violada:** `CHECK (estoque >= 0)`.
3. **Corrigido:**

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Webcam', 300.00, 2, 1);
```

---

### D

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Headset', 450.00, 5, 9999);
```

1. **Problema:** categoria inexistente.
2. **Restrição violada:** `FOREIGN KEY` (integridade referencial).
3. **Corrigido:** usar um `id_categoria` que exista na tabela `categoria` (ex: 1, se existir):

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Headset', 450.00, 5, 1);
```

## Exercício 20 — Um novo problema

Para mostrar somente produtos que atendem a uma condição, usamos a cláusula `WHERE` (que será estudada a seguir):

**Somente produtos que custam mais de R$ 500,00:**

```sql
SELECT *
FROM produto
WHERE preco > 500.00;
```

**Somente produtos da categoria Informática:**

```sql
SELECT *
FROM produto
WHERE id_categoria = 1;
```

> Substitua `1` pelo `id_categoria` real da categoria Informática na sua base.

**Somente o produto chamado Notebook:**

```sql
SELECT *
FROM produto
WHERE nome = 'Notebook';
```

A estrutura geral é:

```sql
SELECT colunas
FROM tabela
WHERE condição;
```
